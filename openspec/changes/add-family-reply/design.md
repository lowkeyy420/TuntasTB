# Design

## Context

After `add-symptom-extraction` the flow returns `family_message`, `nurse_line` and `citations` empty and the family sees the static per-level text from `rules/triage-table.json`. This change makes the flow write a grounded explanation and puts a filter between the flow and the screen. Requirements are in `specs/family-reply/spec.md`.

## Goals / Non-Goals

**Goals:**

- The LLM contributes one thing: a short explanation of what the symptom usually means, quoted from a corpus section.
- Everything with clinical weight (the action, the contact, the fallback) is fixed text.
- A single filter module used by check-in replies, by Q&A later, and mirrored by the eval harness.

**Non-Goals:**

- Making the filter clever. It is a blocklist; when in doubt it replaces.
- A complete guideline library. The corpus covers the triage table's symptoms and the common questions.

## Decisions

### Reply composition

```
<explanation>            generated, or levels[level].message_id
<action>                 always levels[level].action_id
Sumber: <display label>  from corpus/manifest.json
<Puskesmas name>: <phone>
```

`composeReply({ level, flowLevel, generated, citations, contact, fallbackUsed })` in `web/src/lib/reply/compose.ts` returns `{ explanation, action, sourceLabel, contactLine, templateUsed, replaceReason }`. The action is never taken from model output, which is how "one action" and "matches the level" hold by construction. For demo day 41 the YELLOW action is extended by a variant used when a stop-intent flag is present: "Jangan berhenti dulu. Tetap minum obat sesuai jadwal. Perawat akan menghubungi Anda dalam 1 hari kerja." Variants are keyed in the triage table as `levels.YELLOW.action_variants.stop_intent`.

Two further static variants cover check-ins with no symptom: `no_symptom` ("Terima kasih sudah melapor hari ini.") and `dose_missed` ("Terima kasih sudah jujur melapor. Kalau ada kesulitan minum obat, ceritakan ke perawat."). Neither says anything about catching up a dose.

### Filter (`web/src/lib/reply/filter.ts`)

`checkGenerated(text, { level, flowLevel, citations, manifest, forbidden })` returns `ok` or the first failing reason, evaluated in this order:

| Reason | Check |
| --- | --- |
| `empty` | no text |
| `level_mismatch` | `flowLevel !== level` |
| `reassurance` | whole-word, case-insensitive `aman` |
| `dosing` | `\d+\s*(mg|miligram)`, `\d+\s*(tablet|butir|kapsul|pil)`, `dosis`, and the phrases in `forbidden_output.dosing` (kurangi, tambah, gandakan, lewati, ganti obat ...) |
| `diagnosis` | phrases in `forbidden_output.diagnosis` ("Anda menderita", "Anda terkena", "didiagnosis", "ini tanda penyakit") and named conditions in `forbidden_output.conditions` |
| `contradiction` | below RED: a stop instruction ("berhenti minum", "stop obat", "hentikan obat"); at RED: a continue instruction ("tetap minum", "lanjutkan minum") |
| `jargon` | any term in `forbidden_output.jargon` |
| `sentence_length` | a sentence longer than 20 words |
| `citation` | not exactly one citation, or its id is not in the manifest |
| `too_long` | words(explanation) + words(action) > 60 |

Words are counted by splitting on whitespace after trimming. The pattern lists live in `rules/lexicon.id.json` under `forbidden_output`, so the Python eval harness counts dosing and diagnosis violations with identical patterns. `checkStatic` runs the same content checks (all but `level_mismatch` and `citation` id lookup) over every template and variant in a unit test, which is what makes an unsafe template edit fail CI.

Alternative considered: asking a second LLM call to judge the first. Rejected: slower, costlier, and not deterministic. A blocklist that over-rejects only costs a more generic sentence.

### Corpus

```
corpus/
  efek-samping-ringan.md      urine color, mild nausea, joint ache, appetite
  efek-samping-perlu-perawat.md   tingling feet, itching, lasting nausea
  tanda-bahaya.md             yellow eyes or skin, vision, rash, vomiting, confusion
  minum-obat-teratur.md       why finishing matters, feeling better is not cured
  ambil-obat.md               pickups, what to do when the schedule is missed
  peran-pendamping.md         what a PMO does
  manifest.json               generated
```

Each file starts with front matter: `id`, `display_title` (neutral, for families), `source` (the guideline or article the text is drawn from, with URL), `review_status` (`draft` or `reviewed`), `reviewed_by`. Each `##` heading is a section with an explicit `{#slug}`. `corpus/manifest.json` is generated by `corpus/build_manifest.py` and lists `{ id: "<doc>#<slug>", label, source, review_status }`. A CI check regenerates it and fails on a diff.

Corpus text is written in the same plain register the reply needs, so retrieved passages can be paraphrased closely. It is drafted from the sources the plan lists and marked `draft` until a clinician reviews it. The corpus body may name the illness where the source does; `display_title` and section labels may not.

### `ingest_corpus` flow

`Directory/File loader → Split Text (by "## " heading, one chunk per section) → embedding connector → Chroma (collection "tuntas_corpus")`. Each chunk carries metadata `section_id` and `label`. The deploy script uploads the corpus files and runs the flow with the collection reset first, so two runs leave one copy of each section. The flow is not enabled as an MCP tool for unattended use ("admin only" in the plan).

### Explain stage in `checkin_triage`

Added after the Risk Score node:

```
... → Risk Score
     → Build Query     (labels of extracted symptoms + mood flags; no raw note)
     → Chroma retriever (top 4)
     → Prompt (explain) (level, symptom labels, retrieved sections with ids)
     → Gemini model     (structured output: { family_message, nurse_line, citation_id })
     → Build Output → Chat Output
```

- The retrieval query is built from symptom labels, not from the family's sentence, so retrieval cannot be steered by the note.
- The prompt (`langflow/prompts/explain.id.md`, Bahasa Indonesia) states: explain what the symptom usually means using only the given sections; at most 35 words; no instructions about medicine; no "aman"; no condition names; cite exactly one `section_id` from the list; if no section fits, return an empty message.
- `Build Output` maps `citation_id` to `citations: [{ id, label }]`.
- For RED the explain stage still runs but the reply's weight is on the fixed action.

### Nurse line

`buildNurseLine(symptomLabels, persistence, riskReasons)` joins the most important facts with " + ": symptom with duration first ("mual 7 hari"), then the top risk reasons in short form ("bilang sudah sembuh"), truncated to 120 characters. The generated `nurse_line` replaces it only when non-empty, within 120 characters and clean of the `dosing` and `diagnosis` checks.

### Storage

`checkins.family_message` stores the composed explanation, `citations_json` the shown citation, `nurse_line` the stored line. A small migration adds `checkins.reply_template_used boolean` and `checkins.reply_replace_reason text`, which record whether the static template was shown and why; the eval report reads them.

## Cross-cutting

- **Redaction**: the explain stage receives symptom labels and retrieved corpus text, not the note. The generated message is produced without identifiers, and the filter would discard nothing sensitive because nothing sensitive is in its input.
- **Audit logging**: `checkin.enrich` gains `meta { reply_template_used, reply_replace_reason }`. Discarded generated text is not stored anywhere.
- **Neutral wording**: display labels and all templates are covered by the forbidden-terms test; the "Sumber:" line shows a neutral label such as "Panduan efek samping obat, bagian keluhan ringan".
- **Bahasa copy**: templates, variants and corpus are plain Bahasa Indonesia; the jargon list and the 20-word sentence cap are the automated proxy for a primary-school reading level, to be confirmed in the usability test.

## Risks / Trade-offs

- [Blocklist misses a novel unsafe phrasing] → The action and fallback are fixed, the prompt forbids instructions, the eval harness red-teams for dosing and diagnosis on every run, and new patterns are added to `forbidden_output` when found.
- [Blocklist over-rejects, so families often see the generic template] → Acceptable; the replace reason is recorded and reported by the eval harness so the prompt can be tuned.
- [Corpus is unreviewed] → `review_status` is in the manifest, shown in the nurse console footer and in eval reports; release needs clinician sign-off.
- [The RED action wording "Berhenti dulu" is itself a medicine instruction] → It is the plan's fixed text, not generated, and is explicitly flagged for the clinician reviewer.
- [Citation is valid but the explanation drifts from the cited section] → Prompt restricts content to the retrieved sections; citation coverage and spot checks are part of the eval run.
